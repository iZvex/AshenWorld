# Прототип боя (этап 2)

## Состав

| Файл | Ответственность |
|---|---|
| `data/balance.json` | Единый источник коэффициентов, параметров героя, противников и навыков |
| `scripts/combat/combatant.gd` | Состояние участника: здоровье, щит, признак жизни |
| `scripts/combat/combat_formulas.gd` | Все формулы урона и проверка критического удара |
| `scripts/combat/combat_catalog.gd` | Чтение боевых данных из файла баланса |
| `scripts/combat/combat_system.gd` | Автоматический бой, смена противников, навыки и откаты, сигналы |
| `scripts/main/main.gd`, `scenes/main/main.tscn` | Рабочий интерфейс: здоровье, лог боя, кнопка навыка |
| `tests/test_combat.gd` | Точечная проверка только боевой логики |

Логика боя не зависит от сцен и узлов интерфейса, поэтому проверяется отдельно, без сборки APK.

## Формулы

Все коэффициенты читаются из раздела `combat` файла `data/balance.json`:

```
снижение_от_защиты = clamp(защита_цели × defense_reduction_per_point, 0, max_defense_reduction)
урон = макс(0, атака) × (1 − снижение_от_защиты) × макс(0, множитель_навыка)
если критический_удар: урон × critical_multiplier
урон_по_здоровью = мин(текущее_здоровье, урон − поглощённое_щитом)
```

Критический удар определяется как `randf() < шанс_крита` с задаваемым зерном генератора, чтобы тесты были воспроизводимыми. Щит поглощает урон до здоровья. Здоровье не уходит ниже нуля, повторный урон по погибшему не наносится.

Формулы находятся только в `combat_formulas.gd` и нигде не дублируются. Изменение коэффициента в `balance.json` сразу меняет результат — это проверяется отдельным тестом.

## Поведение

- Герой и текущий противник атакуют автоматически с интервалом `attack_interval_seconds`.
- После гибели противника выдаётся сигнал `enemy_defeated` и появляется следующий из списка.
- Когда противники заканчиваются, бой останавливается.
- `Тяжёлый удар` наносит урон с множителем и уходит на откат; повторное применение до окончания отката запрещено, кнопка в интерфейсе блокируется и показывает оставшееся время.
- `Пепельный щит` добавляет щит в размере доли от максимального здоровья героя.
- При гибели героя выдаётся сигнал `hero_defeated`, бой останавливается.

## Тестовые сценарии

| Сценарий | Ожидание |
|---|---|
| Урон без защиты | Равен атаке |
| Критический удар | Умножается на коэффициент из баланса |
| Защита цели | Снижает урон, но не больше предела |
| Подмена коэффициента в данных | Результат формулы меняется |
| Нулевая и отрицательная атака | Урон равен нулю |
| Щит | Поглощает урон раньше здоровья |
| Избыточный урон | Здоровье не становится отрицательным |
| Погибший участник | Не получает урон повторно |
| Автоатаки | Герой и противник наносят урон по таймеру |
| Смена противников | Все противники повержены, бой завершён |
| Навык и откат | Первое применение разрешено, второе запрещено, после отката снова разрешено |
| Неизвестный навык | Не применяется |
| Гибель героя | Сигнал выдан один раз, бой остановлен |

## Запуск проверки

```bash
godot --headless --path . --editor --quit          # разбор новых скриптов
godot --headless --path . --script tests/test_combat.gd
godot --headless --path . --quit-after 120         # быстрый запуск обновлённой сцены
```

По договорённости на этом этапе проверяется только добавленная боевая логика: тяжёлая сборка APK на каждом коммите не запускается. При необходимости полный прогон запускается вручную командой `gh_ops.py dispatch`.
