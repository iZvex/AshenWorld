# Прототип боя (этап 2, расширение этапа 5)

## Состав

| Файл | Ответственность |
|---|---|
| `data/balance.json` | Единый источник коэффициентов, параметров героя, противников и навыков |
| `scripts/combat/combatant.gd` | Состояние участника: здоровье, щит, признак жизни |
| `scripts/combat/combat_formulas.gd` | Все формулы урона, защиты, сопротивления, крита и уклонения |
| `scripts/combat/combat_catalog.gd` | Чтение боевых данных из файла баланса |
| `scripts/combat/combat_system.gd` | Автоматический бой, новые параметры, смена противников, навыки, откаты, помощь питомца и сигналы |
| `scripts/main/main.gd`, `scenes/main/main.tscn` | Компактный экран кампании: здоровье героя и противника в одной строке, этапы, награды, быстрые навыки, панель прогрессии и лог |
| `tests/test_combat.gd` | Точечная проверка только боевой логики |

Логика боя не зависит от сцен и узлов интерфейса, поэтому проверяется отдельно, без сборки APK. Пятый этап расширил участника боя раздельными физической и магической атаками, множителем крита, скоростью атаки, вампиризмом, сопротивлением, уклонением и восстановлением здоровья; эти поля описаны в `docs/progression.md`.

## Формулы

Все коэффициенты читаются из раздела `combat` файла `data/balance.json`:

```
снижение_от_защиты = clamp(защита_цели × defense_reduction_per_point, 0, max_defense_reduction)
урон = макс(0, атака) × (1 − снижение_от_защиты) × макс(0, множитель_навыка)
если критический_удар: урон × множитель_крита_участника
урон ×= 1 − clamp(сопротивление_цели, 0, max_resistance)
шанс_уклонения = clamp(уклонение_цели, 0, 1)
урон_по_здоровью = мин(текущее_здоровье, урон − поглощённое_щитом)
```

Множитель крита берётся у атакующего; значение по умолчанию из баланса применяется только когда он не передан. Критический удар и уклонение определяются как `randf() < шанс` с задаваемым зерном генератора, чтобы тесты были воспроизводимыми. Щит поглощает урон до здоровья. Здоровье не уходит ниже нуля, повторный урон по погибшему не наносится.

Формулы находятся только в `combat_formulas.gd` и нигде не дублируются. Изменение коэффициента в `balance.json` сразу меняет результат — это проверяется отдельным тестом.

## Поведение

- Герой и текущий противник атакуют автоматически с интервалом `attack_interval_seconds`; интервал героя уменьшается от скорости атаки и ограничен `min_attack_interval`.
- После гибели противника выдаётся сигнал `enemy_defeated` и появляется следующий из списка.
- Когда противники заканчиваются, бой останавливается.
- `Тяжёлый удар` наносит урон с множителем и уходит на откат; повторное применение до окончания отката запрещено, кнопка в интерфейсе блокируется и показывает оставшееся время.
- `Пепельный щит` добавляет щит в размере доли от максимального здоровья героя.
- Лечение навыков, вампиризм и восстановление здоровья возвращают здоровье через один метод `Combatant.heal()`, не превышая максимум; лечение выдаёт отдельный сигнал.
- Уклонение полностью отменяет попадание и выдаёт сигнал `attack_dodged`.
- Выбранный питомец периодически наносит долю атаки героя по тем же формулам, выдаёт сигнал и может быть подключён к уже идущему бою.
- При гибели героя выдаётся сигнал `hero_defeated`, бой останавливается.
- Босс из данных кампании однократно усиливает атаку при достижении `phase_threshold` и выдаёт сигнал `enemy_phase_started`. Порог и множитель задаются в `data/balance.json`.

## Тестовые сценарии

| Сценарий | Ожидание |
|---|---|
| Урон без защиты | Равен атаке |
| Критический удар | Умножается на коэффициент из баланса или множитель участника |
| Сопротивление | Снижает уже рассчитанный урон в заданных пределах |
| Уклонение | Отменяет урон и выдаёт сигнал |
| Защита цели | Снижает урон, но не больше предела |
| Подмена коэффициента в данных | Результат формулы меняется |
| Нулевая и отрицательная атака | Урон равен нулю |
| Щит | Поглощает урон раньше здоровья |
| Избыточный урон | Здоровье не становится отрицательным |
| Погибший участник | Не получает урон повторно |
| Автоатаки | Герой и противник наносят урон по таймеру; ускоренная атака даёт больше ударов |
| Смена противников | Все противники повержены, бой завершён |
| Навык и откат | Первое применение разрешено, второе запрещено, после отката снова разрешено |
| Неизвестный навык | Не применяется |
| Лечение и вампиризм | Восстанавливают здоровье, но не выше максимума |
| Помощь питомца | Наносит урон по таймеру и выдаёт отдельный сигнал |
| Гибель героя | Сигнал выдан один раз, бой остановлен |

## Запуск проверки

```bash
godot --headless --path . --editor --quit          # разбор новых скриптов
godot --headless --path . --script tests/test_combat.gd
godot --headless --path . --script tests/test_progression.gd
godot --headless --path . --script tests/test_campaign.gd
godot --headless --path . --script tests/test_ui.gd
godot --headless --path . --quit-after 120         # быстрый запуск обновлённой сцены
```

По договорённости на этом этапе проверяется добавленная боевая логика и ближайшие регрессии: тяжёлая сборка APK на каждом коммите не запускается. При необходимости полный прогон запускается вручную командой `gh_ops.py dispatch`.
